# Pi 1.0.4 upgrade

Piano's exact coding-agent dependency moves from 1.0.2 to 1.0.4, the npm `latest`
reported on October 7, 2026. The lockfile also resolves agent-core, ai, codemode,
mcp, tui, telemetry and chord to 1.0.4. npm additionally updates the compatible
transitive `@babel/runtime` from 7.29.7 to 7.29.10; Effect stays pinned.

## What matters to Piano

Primary source: the published package's `CHANGELOG.md`, sections 1.0.3 and 1.0.4
([upstream changelog](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/CHANGELOG.md)).
These are upstream release claims, not individually reproduced fixes.

- **Session reliability:** cancelling during OAuth refresh no longer invalidates
  subscription refresh tokens. Particularly relevant to Piano's Stop action.
  MCP shutdown now closes transports even while a server is still connecting;
  useful for one-child-per-session lifecycle management.
- **Images:** codemode `image()` saves a reusable temporary file and reports its
  path; `tools.read()` now returns image blocks usable by `image()`. Useful for
  screenshot/design workflows. Generated images, binary MCP resources and
  truncated-output files become user-readable only. These do not by themselves
  add a Piano image gallery or artifact download UI.
- **Tool policy:** `--tools`/`--exclude-tools` support wildcards; `--no-mcp`
  disables MCP for one invocation. `--tools` retains MCP tools unless a selector
  starts with `mcp__`. Useful for future restricted session profiles or diagnosis,
  not a reason to duplicate Pi's configuration loader in Piano.
- **MCP interoperability:** OAuth registration uses a native client, fixing
  `invalid_redirect_uri` with some OpenID Connect servers.
- **Codemode robustness:** frozen built-ins prevent prototype patches crashing
  Pi and leaving tool calls unsettled; hidden tools no longer leak into prompt
  guidelines. Both improve long-running sessions without Piano UI changes.
- **Provider fixes:** stalled Bedrock HTTP/2 streams get automatic retries.
  Azure Foundry Chat Completions adds DeepSeek V4 Pro support.
- Terminal editor navigation and terminal syntax-highlighting fixes are not
  changes to Piano's React editor or transcript rendering.

**Migration warning:** 1.0.3 renames `azure-openai-responses` to `azure`.
Azure users must update provider references in their Pi auth/models/settings
(or log in again). Existing old-provider sessions fall back to another model
and do not reuse their prompt cache. `AZURE_OPENAI_*` variables are unchanged.
No user configuration or credentials were inspected or modified for this bump.

Recommendation: take the runtime fixes now. Consider tool-policy profiles and
image artifact presentation separately if a concrete user journey needs them;
this upgrade introduces no new Piano controls or protocol translation.

Environment: Node 24.21.0, base revision `8043e64` plus this dependency diff.
Evidence retained locally at `/tmp/piano-pi104/` (not registry state).

- `npm test`: **69/69 passed**, no skips (`test.log`). Existing suites include
  real-Pi checks as well as fake-protocol contracts; no new regression warranted
  for the dependency declaration alone.
- `npm run typecheck`: passed (`typecheck.log`).
- Real locked Pi with a scratch fixture CLI wrapper and local synthetic model,
  driven through `npx agent-browser`: **passed supported upgrade journey**
  (`browser-pass/result.json`, commands, screenshots, server logs and Pi facts).
  Covered prompt/command handling, dialog answer after reload, selected project
  model and high thinking, project MCP disable override, native abort, child exit
  and reload without replay. No paid model calls or real registry changes.
- Used scratch ports 7271/7272 for the final run because 7171/7172 became occupied.
  The fixture shuts down its own processes and deletes scratch session/repo data.
- The historical `test/browser-phase0.mjs` has drifted: initial model can be
  project or global, effort is now a radio, handled text changed, and exited
  host state survives reload. A scratch copy adapted those expectations;
  the exact executed copy is retained as `browser-supported-script.mjs`.
  Earlier failed attempts are retained, not represented as passes.
- The historical startup-dialog timeout expectation also failed. That additional
  unsupported-startup check was excluded from the final supported journey;
  this upgrade makes **no claim about startup-dialog compatibility** and does
  not change the checked-in historical test or application behavior to mask it.
- `npm audit` still reports eight high findings in the shadcn-related dependency
  graph (`audit.json`); this Pi bump is not a general dependency-security cleanup.

No build, service restart or deployment was performed. External CLI overrides,
real provider OAuth, Azure migration and the individual upstream fixes were not
exercised; the fixture wrapper imports the locked repository CLI.
