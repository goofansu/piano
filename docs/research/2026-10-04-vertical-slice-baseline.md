### Inferred risks — not reproduced failures

- **Duplicate/interrupted ownership (INV-02):** concurrent opens or path aliases can spawn competing children; release/reopen can overlap. WsClient forks every request while mutating shared selection/attachment, so rapid select/start/action interactions need a public-protocol race check ([request fibers](../../server/WsClient.ts#L193-L214)). Sequential reuse is not concurrency proof.
- **Duplicate or abandoned dialog (INV-04):** two answers can both pass the known-dialog check; Pi-side timeout can leave a retained stale modal; abort can leave an extension blocked. Pi's dialog map/timeout cleanup emits no resolution record here, and normal RPC abort only calls session abort ([Pi dialog implementation](../../node_modules/@earendil-works/pi-coding-agent/dist/modes/rpc/rpc-mode.js#L40-L86), [abort dispatch](../../node_modules/@earendil-works/pi-coding-agent/dist/modes/rpc/rpc-mode.js#L327-L330)). Enqueue success is not proof that a dialog response reached Pi.
- **Wrong projection or memory growth (INV-05):** stale attachment output can affect a newer selection; duplicate events are not detected; reconnect during a tool/partial message cannot reconstruct it from the snapshot alone; an indefinitely slow consumer can accumulate output. The local snapshot lock is useful but does not prove the whole WS/browser journey.
- **Settings/error ambiguity (INV-03,12):** requested-effort patch can contradict Pi's clamped `thinking_level_changed`; filtered message errors can make provider failure appear unexplained. Pi clamps before emitting the effective level ([Pi effort](../../node_modules/@earendil-works/pi-coding-agent/dist/core/agent-session.js#L2010-L2035)). A missing response from a still-live child can stall an action or record processing indefinitely.

## Pi 1.0.2 fixture constraints from primary documentation/source research

These refine verification design, **not runtime results**. Read the installed 1.0.2 RPC commands,
CLI, message/session formats, extensions, MCP, environment/configuration/settings, model/virtual-model
and SDK docs in full, plus relevant security/resource/compaction/UI references and examples.

- **Trust and MCP:** headless RPC cannot display Pi's built-in trust prompt; untrusted project
  resources may be skipped. A scratch-only trusted project disabling a disposable global MCP
  sentinel must be paired with a connecting control, so globally broken/disabled MCP cannot pass.
  Inspect via `/mcp` without a model call. Preserve built-in extensions and normal CLI loading;
  do not add production automatic trust. Offline mode alone does not stop arbitrary extension or
  MCP traffic. [trust](https://github.com/earendil-works/pi/blob/v1.0.2/packages/coding-agent/docs/security.md#project-trust-without-an-interactive-prompt),
  [MCP](https://github.com/earendil-works/pi/blob/v1.0.2/packages/coding-agent/docs/mcp.md#configuration-rules),
  [environment](https://github.com/earendil-works/pi/blob/v1.0.2/packages/coding-agent/docs/environment-variables.md).
- **Preflight/busy commands:** a command dialog can precede its prompt acknowledgement and occur
  without an agent run. `prompt` with explicit busy behavior preserves extension commands;
  `follow_up` rejects them. Ordinary input during compaction may reject. A handled disposition is
  not proof the extension command succeeded. Abort does not clear queues; name/test the stop policy.
  [commands](https://github.com/earendil-works/pi/blob/v1.0.2/packages/coding-agent/docs/rpc-commands.md#prompt),
  [queue stop](https://github.com/earendil-works/pi/blob/v1.0.2/packages/coding-agent/docs/rpc-commands.md#clear_queue).
- **Deadline uncertainty:** Pi starts timeout before stdout delivery and sends no standard UI reply
  acknowledgement/closure event; receipt-time deadlines are host estimates. Unknown/expired response
  IDs are ignored. Arbitrary extension signal cancellation is not fully observable from standard RPC;
  document bounded recovery instead of inventing closure. Use command-triggered baseline dialogs.
  Source inspection identifies a separate unproved startup limitation: RPC awaits extension binding
  before installing its stdin reader, so an awaited blocking `session_start` dialog may prevent
  readiness/answer handling. Reproduce before claiming support.
  [UI](https://github.com/earendil-works/pi/blob/v1.0.2/packages/coding-agent/docs/rpc-extension-ui.md),
  [installed startup sequence](../../node_modules/@earendil-works/pi-coding-agent/dist/modes/rpc/rpc-mode.js#L229-L289),
  [installed reader](../../node_modules/@earendil-works/pi-coding-agent/dist/modes/rpc/rpc-mode.js#L640-L651).
- **Display/accounting scope:** `get_messages` is current model context, not all raw entries/history.
  Final message/block endings are authoritative; nested execution events do not create extra transcript
  messages, and parent result usage already includes nested usage. A consistent compaction/reopen
  display scope and Pi-owned session totals avoid duplicate history/accounting.
  [history commands](https://github.com/earendil-works/pi/blob/v1.0.2/packages/coding-agent/docs/rpc-commands.md#get_messages),
  [events](https://github.com/earendil-works/pi/blob/v1.0.2/packages/coding-agent/docs/json.md#reconstruct-streaming-messages),
  [tool usage](https://github.com/earendil-works/pi/blob/v1.0.2/packages/coding-agent/docs/message-types.md#toolresultmessage).

No fixture above was created or executed during this research. Fake Pi validates Piano translation;
local synthetic-provider real-Pi checks can validate runtime mechanics without paid calls, but neither
establishes hosted-provider/model quality or credentials. Build that stronger fixture only for a
concrete remaining compatibility claim, not as a prerequisite for every phase.
